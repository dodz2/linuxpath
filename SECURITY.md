# Politique de sécurité

## Versions prises en charge

La branche `main` et le site GitHub Pages correspondant reçoivent les correctifs de sécurité. Les révisions historiques ne sont pas maintenues séparément.

## Signaler une vulnérabilité

Utilisez exclusivement le canal privé **[Signaler une vulnérabilité](https://github.com/dodz2/linuxpath/security/advisories/new)** de GitHub.

Ne publiez pas de détail exploitable dans une issue, une discussion, une pull request ou un dépôt public. Indiquez, dans le signalement privé :

- le composant et la révision concernés ;
- les étapes minimales de reproduction ;
- l’impact observé, sans donnée personnelle ni secret ;
- une proposition de correction, si disponible.

Un accusé de réception sera donné dès que le rapport aura été lu. La validation, la coordination de la correction et la divulgation éventuelle doivent rester privées jusqu’à accord explicite.

## Périmètre

Le terminal et les CTF sont des simulations pédagogiques exécutées dans le navigateur. Un comportement volontairement simulé n’est pas, à lui seul, une vulnérabilité. Les contournements de sécurité du site, les injections, les fuites de données, les dépendances compromises et les défauts du processus de déploiement sont en revanche dans le périmètre.
